Your coding agent drives fast. The harness keeps it on the road.

Six small tools that check what a coding agent decides, runs, commits and pushes, on your machine, and let CI skip what your laptop already proved. Plus a design system themed by your tokens. Every part is optional. Take the ones you need.

your colours

Theme

Start from a preset, then change only the four colours that define it. The page and the game follow as you go, and your choice stays in this browser.

The other 23 colour tokens (hover, borders, cards, status backgrounds) are derived from these four.

Each colour is checked against the contrast it needs: a low one is flagged, never blocked.

human in the loop

Where you are in the loop

The agent drives between these points without asking. At these points it stops for you.

S1 · decideYou decideYou write and accept the ADRs. The harness only reads them, and stops when two of them disagree.
S1 · planYou approve the planReviewer agents read it first. Nothing is built until you say yes.
S1 · first taskYou trust a repo onceThe first task in a new repository asks you before the router works in it.
S3 · review, mergeYou look, and you answerUI changes open in your browser. The agent asks only what the plan left open, or anything destructive.
S3 · learnYou approve harness changesA new rule or skill goes in only when you accept it.
self-improvement

The pit lane: how the harness gets better each lap

Every rule in the harness today came from a real slip on an earlier lap. This is the loop that turns one into the other.

  1. A slipA command fails silently, a wrong stash is popped, time is lost on a guess.
  2. The retro finds itThe retro skill reads the sessions and finds where time or quality was lost.
  3. It proposes a fixA new rule, a change to a skill, or an ADR, aimed at the cause.
  4. You approve itNothing changes in the harness without you.
  5. It ships as a warningThe new rule first advises the agent instead of blocking it, so a false alarm costs nothing.
  6. It earns its placeA rule that proves right becomes a block. One that does not pay for itself is removed.
The router learns on every taskIt records which model and effort got each kind of task accepted, so the next one starts cheaper.
The track stays cleanworktree-sweep removes finished worktrees and stops the language servers left running in them, so old work never leaks into the next lap.
